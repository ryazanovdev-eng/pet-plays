## 9. 2.5D и оптимизация (предварительное направление)

Пользователь выбрал 2.5D с лёгкими или отсутствующими текстурами и приоритетом оптимизации. Окончательное решение фиксируется в `docs/03-art-bible.md`.

Два допустимых варианта:

1. **3D low-poly + ортокамера.** Простые меши, плоские материалы, фиксированный ракурс.
2. **2D-спрайты в 3D-пространстве.** Один раз смоделировать объект и отрендерить кадры с фиксированных углов — это консистентнее, чем генерировать каждый кадр нейросетью.

Правила производства:

- 1 unit = 1 метр; пивот персонажа у ног.
- 500–3000 треугольников на игровой объект, если не согласовано иное.
- Flat-материалы или vertex colors вместо тяжёлых PBR-текстур.
- Один материал на объект или общий атлас.
- Без real-time теней; AO запекать в vertex colors.
- Текстуры только там, где без них не читается форма; 256–1024 px.

Чек-лист оптимизации:

- [ ] Рендер `gl_compatibility`, окно 1280x720.
- [ ] Повторяющиеся объекты через `MultiMeshInstance`.
- [ ] Пул объектов вместо постоянного `instantiate/free`.
- [ ] Отключение обработки за экраном (`VisibleOnScreenNotifier`).
- [ ] Нет аллокаций в `_process`, если можно обойтись.
- [ ] Проверка на целевой видеокарте GTX 1060 3 ГБ.
- [ ] 60 FPS в тестовой сцене с реалистичным числом объектов.
