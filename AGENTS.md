# pet-plays — инструкции для ИИ-агентов

## 1. Язык и стиль
- Общайся с пользователем по-русски. Документация и отчёты — по-русски.
- Код, имена файлов и папок, классы, функции, ветки, коммиты — по-английски.
- Пользователь — новичок в геймдеве и промтинге. Объясняй решения простыми словами и всегда предлагай конкретный следующий шаг.
- Не используй жаргон без короткой расшифровки.

## 2. Проект
- Небольшая игра на **Godot 4.7.2**, язык **GDScript**.
- Репозиторий: https://github.com/ryazanovdev-eng/pet-plays
- Текущий этап: **M3 на повторной визуальной приёмке; M4 не начат**. Решение о визуале принимает пользователь. Отчёт QA о предыдущей версии не подтверждает текущую.
- Главный документ процесса: `docs/00-pipeline.md`. Перед началом работы прочитай его и профильные документы этапа.
- В демо M3 сцены без игровой логики: центр с боссом, край у леса, рядовая волна, выбор улучшения, магазин и галерея каста. Не показывай арену целиком. Пути к сценам см. в `README.md`; раскладку HUD по состояниям см. в `docs/03-art-bible.md`.
- Покадровый арт из `raw/` сохраняй в нативном разрешении без потерь, с общей опорой по стопам. Публикуй размеры и темп клипов только после подтверждения. Blender не входит в демо: исходник отклонённого пилота сохраняй как архив, не удаляй и не возвращай в показ. Детали: `docs/06-asset-pipeline.md`.

## 5. Команды
```powershell
.\tools\godot.cmd -Editor     # открыть редактор Godot
.\tools\godot.cmd             # запустить игру
.\tools\check.cmd             # headless-проверка: импорт + один кадр главной сцены
python tools\gen_image.py "prompt" --size 1024x1024 --seed 42
python tools\mcp_probe.py --name godot --call get_godot_version -- cmd /c npx -y @coding-solo/godot-mcp
```

`*.cmd` — надёжная обёртка: запускает `*.ps1` с `-ExecutionPolicy Bypass`, поэтому работает даже при запрете сценариев PowerShell. Внутри скриптов и в VS Code tasks используй `.cmd`.

## 5.1. MCP-серверы
Подробности и диагностика: `docs/05-mcp.md`.

| Сервер | Что делает | Обязательное условие |
|---|---|---|
| `blender` | Создаёт и меняет 3D-сцену, материалы, рендеры, импорт low-poly | Blender открыт, аддон MCP for Blender включён, сервер запущен |
| `godot` | Запускает редактор и проект, читает debug-вывод, создаёт сцены и узлы | Проект содержит `project.godot`, `GODOT_PATH` верный |
| `fal` | Изображения, видео, музыка, аудио через fal.ai | Токен в глобальном конфиге, `enabled: true` |

Правила:
- MCP-инструменты в `permission` стоят на `ask`: каждый вызов подтверждает пользователь.
- Перед изменениями сцен через MCP убедись, что рабочее дерево закоммичено или пользователь разрешил правки.
- Источник правды по сборке — `.\tools\check.cmd`. MCP помогает, но не заменяет проверку.
- Не запускай два MCP-сервера, которые одновременно правят одни и те же сцены.
- Ключи API — только в глобальном конфиге Kilo, не в проектном `kilo.json`.
- После изменения `kilo.json` нужен reload окна VS Code.
- `/mcps` — команда CLI/TUI Kilo. В VS Code-расширении её может не быть в списке слэш-команд; проверяй загрузку по доступности инструментов и через `tools/mcp_probe.py`.

## 5.2. Бюджет
- **fal.ai: не больше $5 на весь проект.** Это политика, а не техническое ограничение.
- Перед платной генерацией вызывай `fal_get_pricing`, после — `fal_get_usage`.
- Дорогие модели (видео, Meshy, 3D) — только с явного согласования.
- При приближении к $5 остановись и спроси пользователя.
- `fal_get_usage` работает только с admin-ключом. Если доступа нет, считай стоимость по `fal_get_pricing` и проси пользователя проверить кабинет fal.
- Решение зафиксировано в `docs/decisions/001-fal-budget.md`.

## 6. Правила работы
- **Сначала документ, потом код.** Любая новая фича сначала появляется в `docs/04-plan.md` и только потом в коде.
- После правок GDScript или сцен запускай `.\tools\check.cmd` и приводи фактический вывод. Нельзя писать «работает» без проверки.
- **Не коммить и не пушь без явной просьбы пользователя.**
- Не редактируй вручную `.godot/`, `*.import` и `.kilo/agent-manager.json`.
- Не добавляй секреты и ключи в репозиторий. Ключи — только в переменных окружения или глобальном конфиге Kilo.
- Godot 4 API: `Node2D`, `CharacterBody2D`, `@export`, `@onready`, `signal`, `Callable`, `Tween`, `await`. Не используй API Godot 3.x.
- Сцены собирай композицией: маленькие сцены, один скрипт — одна ответственность.
- Не используй длинные пути `get_node("../../..")`. Применяй `@onready` и уникальные имена `%Name`.
- Не генерируй текст на изображениях: AI делает это плохо. Текст в UI — кодом Godot.
- Финальные ассеты кладём только в `assets/`, концепты — в `docs/art/`.

## 7. Подагенты
| Агент | Когда использовать |
|---|---|
| `producer` | Оркестрация этапов, рамки MVP, план работ |
| `game-designer` | Концепт, core loop, механики, GDD |
| `art-director` | Визуальный стиль, арт-библия, отбор концептов |
| `prompt-smith` | Промты для изображений, 3D, анимаций, аудио |
| `tech-artist` | Импорт ассетов, 2D/3D-пайплайн, анимации |
| `godot-dev` | Код и сцены Godot |
| `qa-tester` | Проверки, отчёты об ошибках, чек-листы |

Делегируй через инструмент Task, не смешивай роли в одном ответе. После делегирования кратко перескажи результат пользователю.

## 8. Чего не делать
- Не расширяй scope без согласования: сначала MVP, потом идеи «на будущее».
- Не придумывай вкусы пользователя — спрашивай.
- Не переходи к следующему этапу пайплайна без явного «согласен».
